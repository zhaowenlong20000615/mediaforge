## 最优先的交付阻断问题

### A01 · P0 · 无认证、无文件范围隔离，并以 root 对外提供服务

位置：[server.py](../../mediaforge/server.py):9–36、40；[core.py](../../mediaforge/core.py):39–58；[activate.sh](../../deploy/activate.sh):11。

HTTP 提交接口直接接受任意路径列表，`inspect()` 只确认文件存在。下载、查询、取消和恢复没有身份校验或资源归属。静态路径也直接拼接，缺少规范化后目录范围校验。本地无认证提交了数据目录外的自建 canary，任务受理为 202，下载为 200，返回内容与 canary 一致；静态路由能够返回静态目录之外的项目 README。

线上同一代码以 UID 0 运行，因此文件泄露影响范围可能扩展到该进程有权读取的服务器文件。**这不是已经确认泄露的结论，而是已验证的权限缺陷及其部署影响。**

修复要求：先限制公开访问，加入认证和任务所属范围；远程客户端只能提交已授权的上传文件 ID；静态文件和输出都做目录边界检查；以独立低权限用户运行。验收必须覆盖未授权访问和路径越界拒绝。

### A02 · P0 · 未完成处理却返回 succeeded

位置：[core.py](../../mediaforge/core.py):78、82–114。

通用分支使用 `shutil.copy2`，图片处理异常也复制原文件，没有在返回结果中说明没有执行。复现结果：

| 请求 | 实际结果 | 返回状态 |
|---|---|---|
| 有效 WAV 语音识别 | 输出仍是逐字节相同的 WAV，没有文字/字幕 | succeeded |
| 无字幕 MP4 提取字幕 | 输出仍是逐字节相同的 MP4 | succeeded |
| 有效 PDF 旋转 90° | 输出与原 PDF 完全相同 | succeeded |
| 文本文件转 PNG | 文件名和 MIME 冒充 PNG，内容仍为文本 | succeeded |
| 空批量请求 | 没有输入、没有输出 | succeeded |

这不是“质量要人工确认”，而是没有执行请求。修复要求：移除复制兜底；未实现、依赖缺失、不支持格式分别返回明确状态；每种操作验收实际结果，例如 PDF 页面旋转值、真实音频编码、图像可解码性、字幕语法及时间轴。

### A03 · P0 · 线上浏览器主流程不能完成

位置：[app.js](../../static/app.js):1，`api()` 和提交处理器。

用自建 64×64 PNG 选择文件并点击创建，页面没有出现任务或错误提示。控制台记录 `Unexpected end of JSON input`，涉及 `api()`、提交处理器与队列刷新。空响应的网络/后端原因本次没有独立定位，不能全部归因于应用服务器。

另独立确认浏览器真实环境为 `isSecureContext=false`，`typeof crypto.randomUUID` 为 `undefined`；提交代码无条件调用该函数。因此即使上传响应正常，当前 HTTP 页面仍存在确定的提交阻断条件。MDN 明确说明该 API 受安全上下文约束：[Crypto.randomUUID](https://developer.mozilla.org/en-US/docs/Web/API/Crypto/randomUUID)。

修复要求：配置 HTTPS、采用可用的幂等键生成方式；检查 HTTP 状态和响应体；显示上传/提交进度与可恢复错误；按下按钮后防重复提交，失败保留已选文件。

- **Sam / 键盘使用者**：无法 Tab 到工具项和上传入口，无法完成主任务；状态改变也没有播报。

## 建议的整改次序与验收

1. **先关闭 P0**：限制当前公开访问、补权限范围，移除“复制即成功”，修通浏览器上传→提交→状态→结果链路。
2. **再补统一业务层**：所有入口共享有事务保护的状态；按原始功能矩阵实现适配器及能力诊断，完成取消、恢复、部分成功、同名输入与真实结果验证。
3. **完成产品界面**：工具目录分组与搜索；工具详情/参数；文件明细；任务详情/日志；结果预览/下载/继续处理；历史与设置。保留暖色工业工作台的视觉方向，把主要空间让给操作。
4. **完成标准 CLI/MCP/Skill 和可靠发布**：干净安装、共享权限、标准握手、稳定错误结果、受监管服务、校验/原子发布/自动回滚。
5. **重新验收**：合成样本应验证实际变换；用户授权的真实样本应验证业务质量。覆盖缺依赖、受保护/损坏文件、Unicode、并发、断网、服务器重启和回滚。未执行项明确留空，不再用健康接口或哈希代替业务证据。

设计技能顺序建议：`/harden`（状态、错误和安全显示）→ `/clarify`（真实能力与数据位置）→ `/arrange`（工作区结构）→ `/adapt`（窄屏/键盘）→ `/typeset`（字号与对比度）→ `/polish`（最后细节）。这些技能只能辅助界面整改，不能替代后端适配器、授权和状态机的工程实现。

验收线：P0/P1 关闭后才考虑对外作为可用产品；发布和推送成功仍需单独保留证据。原需求已经明确要求完整交付，无需再让用户为这些缺口重新选择范围。
